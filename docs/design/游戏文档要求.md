# 游戏文档要求

## 一、游戏设计流程（总览）

| 阶段 | 产出文档 |
|------|----------|
| 游戏概念设计 | 概念设计文档 |
| 游戏建议书 | 游戏建议书 |
| 游戏设计 | 设计说明书 |
| 游戏技术设计 | 技术设计说明书 |
| 游戏关卡设计 | 关卡设计说明书 |
| 搭建原型系统 | （可玩/可演示的原型，无单独文档名） |

**要做什么：** 按上表顺序推进项目，最终产出 5 类文档 + 1 个可验证的原型。

---

## 二、概念设计文档

### 定位与写法

- 关于游戏设计的纲领性想法
- 用 **1–3 句话** 做定性描述
- 总结性描述主要人物和角色
- 第一时间激发读者兴趣
- 若不能用几句话概括 → 说明还没想明白

### 结构要求

**必须包括：**

- 整体介绍
- 内容描述
- 主要的特征
- 类型、口味
- 平台类型

**也可以包括：**

- 背景介绍
- 呈现风格

### 你要完成的事

1. 写一份 **极简、高概念** 的文档（类似电梯演讲）
2. 用 1–3 句话说清楚「这是什么游戏」
3. 概括主角/核心角色
4. 补齐：类型、平台、核心卖点；可选背景与美术风格

---

## 三、游戏建议书

### 用途与重点

- 一般用于获得下一步的投资
- 是给第三方或是发行方看的
- 需要包含足够的细节，以便于别人评估这个游戏创意
- 仍然是概要性的，但是需要明确：
  - **游戏基调**
    - 我想让大家看到什么样的效果？
    - 通过游戏我又想表达什么样的想法？
  - **明确玩家的任务**
    - 如何从游戏中获得乐趣

### 篇幅与定位

- 是对游戏概念设计某种程度的扩展
- 充分表明你想要达到的目标
- 通常 **5–50 页**

### 必须包括

1. 修改后的概念
2. 玩家对象分析
3. 技术分析
4. 时间安排
5. 预算
6. 风险
7. 支出与收益预计
8. 艺术实现

### 你要完成的事

1. 在概念文档基础上 **扩写**，面向投资人/评审方
2. 写清：视觉与情感基调、想传达的主题、玩家目标与乐趣来源
3. 补齐：受众、技术、工期、预算、风险、收支、美术方向
4. 篇幅约 5–50 页（课程作业可酌情精简，但结构要齐）

---

## 四、技术设计说明书

- 回答 **怎么实现** 游戏的设计
- 包含架构的视图，需要使用的技术
- 一些工程开发的细节
- 一些游戏出品的细节
- 由技术主管或首席工程师负责完成
- 对技术上的困难有充分的预估，并提供解决或替代方案

### 你要完成的事

1. 把设计说明书里的玩法 **翻译成技术方案**
2. 画架构图，列技术栈（引擎、语言、框架等）
3. 写模块划分、数据结构、关键算法、开发流程
4. 列出技术风险及备选方案（性能、平台、网络等）

---

## 五、游戏设计说明书（GDD）

### 定位

- 回答「这个游戏是什么」
- 充实游戏内容：干巴巴的大纲变成有血有肉的、实实在在的描述
- 描述故事情节发展：围绕「如何赢得游戏」这个总体目标，包括游戏对玩家的挑战与玩家的体验
- 提供从艺术实现角度对这个游戏的看法
- 由游戏设计者维护，并需要不断完善
- 游戏开发中的 **「圣经」**

### 必须包含

1. 游戏的机制
2. 用户界面
3. 视觉上的要求/效果
4. 声学上的要求/效果
5. 角色设计
6. 情节设计
7. 游戏的结构
8. 关卡的大概说明

### 角色与情节（补充要求）

**角色设计：**

- 对于动作、冒险和 RPG 游戏而言，需要有一个鲜明的、强有力的主角来吸引观众的注意力
- NPC 的形象也非常重要

**情节设计：**

- 设计冒险和 RPG 游戏的基础
- 对于按等级划分的战略游戏而言，较强的故事性能够增加游戏的趣味性

### 你要完成的事

1. 写 **最完整、最细** 的设计文档，作为团队主参考
2. 逐项展开：机制、UI、视听、角色、剧情、整体结构、关卡概要
3. 重点写清：怎么赢、玩家挑战、体验曲线、美术方向
4. 角色/NPC 要有辨识度；剧情与玩法目标挂钩
5. 持续迭代更新（不是一稿定死）

## 六、关卡设计说明书

### 如何拆分关卡

绝大部分游戏故事能够划分为彼此独立的段落：

- 过关游戏可按难度分级
- RPG 和冒险游戏具有情节、场景、地图等
- 体育游戏分为队伍、场地、课程训练等
- 军事和历史游戏包括军队、武器，以及作战环境等因素

扩充游戏每一章节：

- 根据难度等级或场景分为相互对立但又关联的部分
- 反复推敲
- 尽可能将任务细分，详细描述每一细节
- 细节层次与文档由游戏类型和开发环境决定

### 每关必须写的内容

- 游戏关卡的命名
- **细节描述：**
  - 外观
  - 背景（环境）
  - 前景（物体、动作）
  - 动画/建模
  - 音乐和音效
  - 场景切换
  - 脚本和交互点
  - 游戏原画设计

### 撰写流程

**循序渐进的扩充：**

- 脚本
- 故事情节
- 开发并完善设计文档，由大致的粗糙描述到确定的完整描述

**流程：**

- 以图的形式表现游戏元素和事件（子目标）之间的关系

### 角色大全/技术手册

- 详细描述每一角色的特点（人物的独特之处）
- 采用何种技术？如何实现？
- 例子：确定关卡的难度

### 你要完成的事

1. 按游戏类型把内容拆成 **可独立开发的关卡/章节**
2. 为 **每一关** 单独写说明（命名 + 上述细节项）
3. 画流程图/关系图，标出元素、事件、子目标
4. 从粗稿迭代到定稿；任务拆到可执行粒度
5. 附角色技术手册（特点 + 实现方式）及难度设计示例

## 七、搭建原型系统

采用下面两种方式中的任何一种：

- 小型的 demo，用于展示某种观点
- 一个类似的交互的故事板（storyboard）

**验证游戏目标，回答三问：**

1. 是否能达到希望的效果？
2. 开发中你还需要做什么？
3. 这个游戏值不值得开发？

### 你要完成的事

1. 不做完整游戏，先做 **可演示原型**（小 demo 或交互故事板）
2. 用原型验证核心玩法/体验是否成立
3. 根据原型结论，列出后续开发清单，并判断项目是否值得继续做

## 八、对照表：每种文档要干什么

| 文档/阶段 | 核心目的 | 你要完成的事 |
|-----------|----------|--------------|
| 概念设计文档 | 一句话讲清游戏 | 1–3 句定性描述 + 角色概要 + 类型/平台/特征 |
| 游戏建议书 | 说服评审/投资方 | 扩写概念 + 受众/技术/工期/预算/风险/收支/美术（约 5–50 页） |
| 设计说明书 (GDD) | 开发「圣经」 | 机制/UI/视听/角色/剧情/结构/关卡概要，持续完善 |
| 技术设计说明书 | 说明怎么实现 | 架构、技术栈、工程细节、技术风险与备选方案 |
| 关卡设计说明书 | 逐关可开发 | 每关命名 + 环境/交互/音效/脚本等 + 流程图 + 角色技术手册 |
| 搭建原型系统 | 验证可行性 | Demo 或交互故事板 + 回答效果/待办/是否值得做 |

---

## 九、建议执行顺序

```
概念设计文档 → 游戏建议书 → 设计说明书 (GDD)
                                    ↓
              技术设计说明书 ←──────┴──────→ 关卡设计说明书
                                    ↓
                            搭建原型系统
```
